# Архитектура RGATU Student Hub

## Слои

### frontend/

Отдельное приложение на Vite. Оно отвечает только за интерфейс, PWA, навигацию и локальный UX.

Frontend не должен знать, откуда физически пришли данные: Excel, HTML РГАТУ, MariaDB или будущий официальный API.

### backend/

Отдельный Yii3 API. Он отвечает за:

- каноническую модель данных;
- авторизацию и роли;
- адаптеры источников;
- расписание;
- профиль студента;
- сессии;
- ДКР;
- задолженности;
- уведомления;
- будущие интеграции с ЛК1/ЛК2.

### MariaDB

Долговременное хранилище нормализованных данных. Исходные документы считаются источниками импорта, а не моделью приложения.

## Контракт

Версионированный API: `/api/v1/*`.

Первый набор:

- `GET /api/v1/meta`
- `GET /api/v1/health`
- `GET /api/v1/groups`

## Миграция

Текущий рабочий модуль расписания не ломается. Сначала он работает как статический модуль внутри Vite, затем его чтение данных переносится на Yii3 API.
