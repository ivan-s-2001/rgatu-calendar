# Архитектура Student Hub

Новый проект строится как **shell + независимые модули + адаптеры источников**. UI не должен зависеть от того, пришли данные из Excel, официального API, ЛК или локального файла.

Модули: расписание; ЛК1/ЛК2; сессии; ДКР; академические задолженности; университетские сервисы; уведомления.

Каждый источник реализует схему fetch/parse -> canonical model. Текущие Excel-файлы — один адаптер. При появлении официального API/SSO меняется адаптер, а экраны остаются.

Безопасность: пароли ЛК не сохраняются; авторизация происходит на официальных доменах; для будущей официальной интеграции нужны OIDC/SAML/SSO или согласованный server-to-server API.

Стабильный `rgatu-schedule` не ломается: Student Hub получает снимок рабочего schedule-модуля, а затем сможет заменить его API-адаптером.
