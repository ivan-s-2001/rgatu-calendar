# Домены университетской системы

Целевая схема интерфейсов:

| Домен | Назначение |
| --- | --- |
| `student.rsatu.ru` | личное пространство студента |
| `teacher.rsatu.ru` | рабочее место преподавателя |
| `admin.rsatu.ru` | административная система |
| `api.rsatu.ru` | единый Yii3 JSON API |

Каждый пользовательский домен — отдельная Vite-сборка. Общими остаются design system, UI-примитивы, типы данных и API-клиент.

## Почему не один интерфейс с переключателем роли

Роли имеют принципиально разные сценарии и информационную плотность. Поддомены дают:

- отдельную точку входа;
- отдельный PWA manifest;
- независимый lifecycle фронтендов;
- возможность разного кэширования и rollout;
- понятные URL для пользователей;
- отсутствие искусственного переключателя ролей внутри интерфейса.

Разделение фронтендов не является механизмом безопасности. Все операции проверяются на `api.rsatu.ru` через Yii3 RBAC + scope.

## Сборки

```bash
npm run build:student
npm run build:teacher
npm run build:admin
```

Результат:

```
frontend/dist/
  student/
  teacher/
  admin/
```

Каждую директорию можно независимо развернуть на своём поддомене.

## Авторизация

Целевая схема:

```
student.rsatu.ru ─┐
teacher.rsatu.ru ─┼─> SSO/auth ─> api.rsatu.ru
admin.rsatu.ru ───┘
```

Frontend не назначает себе роль. После входа backend возвращает пользователя, роли, permissions и scopes. Если преподаватель вручную откроет `admin.rsatu.ru`, сервер всё равно не выдаст ему административные данные или команды.
