# RBAC и области полномочий

Система не использует простую модель `role = admin|teacher|student`. Для РГАТУ нужна комбинация:

```
роль + область действия + срок действия
```

Область действия задаётся через `user_role_assignment`:

- `org_unit_id` — институт, факультет, кафедра, ФЗО или другое подразделение;
- `group_id` — конкретная учебная группа;
- оба поля NULL — глобальная область, допустимая только для ограниченного набора ролей;
- `valid_from / valid_to` — срок назначения.

## Пример старосты

Староста остаётся студентом и получает дополнительное назначение:

```
role = group_leader
group_id = <своя группа>
```

Разрешение `group.attendance.mark` всегда проверяется вместе с совпадением `group_id`.

Староста не получает права на оценки, учебный план, ведомости или расписание.

## Преподаватель

Преподаватель не является владельцем учебного процесса.

Базовые права:

- смотреть назначенную нагрузку;
- проверять назначенные работы;
- вводить оценку там, где это разрешено;
- заполнять уже открытую администрацией ведомость.

Он не получает:

- `group.manage`;
- `curriculum.manage`;
- `schedule.manage`;
- `sheet.manage`;
- `student.manage`.

## Административные роли

Полномочия администратора также ограничиваются областью подразделения.

Например сотрудник деканата с `org_unit_id = ФЗО` не должен автоматически получать права на другие институты.

Глобальные права используются только для учебного управления, администрации университета и системных администраторов там, где это действительно необходимо.

## Проверка доступа в Yii3

Право считается разрешённым только если одновременно выполняются:

1. у пользователя есть активное назначение роли;
2. роль содержит требуемый permission;
3. назначение действует на текущую дату;
4. scope назначения покрывает объект операции;
5. дополнительные бизнес-правила разрешают изменение состояния объекта.

RBAC не заменяет workflow. Например `teacher.sheet.fill` не позволяет редактировать закрытую ведомость.

## Audit trail

Все административные и юридически значимые изменения должны попадать в `audit_log`:

- кто;
- когда;
- какое действие;
- над какой сущностью;
- старое состояние;
- новое состояние;
- request id;
- дополнительный контекст.

Закрытые ведомости, оценки, статусы студента и назначения ролей нельзя изменять без журналирования.
